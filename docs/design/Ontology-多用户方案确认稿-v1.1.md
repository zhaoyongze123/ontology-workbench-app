# Ontology 多用户方案确认稿 v1.1

日期：2026-10-19。状态：用户已整体确认以下 15 项功能规则，功能方案定稿；技术方案另行逐项科普和确认，尚未开始代码、数据库或服务配置实施。

## 已确认的产品规则

1. **按项目协作**：项目默认私有，创建者可邀请成员共同查看或编辑。
2. **账号开通**：Workbench 首次登录验证成功后自动创建 Ontology 内部账号；账号密码用户由系统管理员邀请创建，不开放密码自助注册。新账号不自动加入已有项目。
3. **项目创建**：所有已启用用户都可以创建项目，并成为项目所有者。
4. **项目角色**：设所有者、管理员、编辑者、查看者四档。所有者可以转移所有权、删除项目；项目管理员协助管理项目及普通成员，不能转移所有权或删除项目；编辑者维护图谱内容而不管理成员；查看者只读并允许导出。
5. **邀请生效**：受邀者接受邀请后才加入项目，接受前没有该项目权限。
6. **邀请对象**：第一版只对已注册的 Ontology 用户发送站内项目邀请，暂不支持邮件邀请未注册用户。项目邀请与系统管理员开通账号是两件事。
7. **导出权限**：查看者也可以导出其有权访问的图谱数据，不能因此访问其他项目或修改数据。
8. **系统管理员**：默认可以查看和管理所有项目。这是区别于项目管理员的全局权限，必须由后端授予和审计，不等于数据库超级用户或任意 SQL 执行权。
9. **账号绑定**：允许用户验证账号密码身份和 Workbench 身份后主动绑定到同一个内部账号，共用项目及权限。不按相同邮箱自动合并。
10. **旧数据归属**：现有项目和图谱先归明确指定的初始系统管理员，再由其转交负责人；普通用户不会自动获得访问权，也不能由第一个登录的人自动接管。
11. **Agent 写入**：允许 Agent 按当前用户权限新增、修改、删除数据，写入前需要用户确认。查看者通过 Agent 仍只能读取及导出。
12. **整张图谱删除**：编辑者不能删除整张图谱；仅所有者、项目管理员或系统管理员可以执行。页面和 Agent 一致。
13. **成员离开后的数据**：退出或被移除即失去成员访问权，但其创建的图谱、节点、关系保留在项目中，由剩余成员按权限维护。系统管理员的独立全局权限不因退出某个项目而自动撤销。
14. **首版层级**：用户 → 项目 → 图谱，不增加团队或组织层，不自动把 Workbench 工作区映射为项目。
15. **嵌入体验**：允许新窗口登录；第三方 Cookie 等浏览器限制导致无法使用内嵌会话时，允许在新窗口使用完整应用。

## 待逐项解释和确认的技术建议

账号密码与 Workbench OIDC 经服务端验证后，统一映射到 Ontology 的内部 user_id。Java 后端统一管理身份、会话、App 授权及项目权限；当前 Python 认证层为过渡实现，正式切换后退出凭证发行职责。

浏览器会话与 Agent 的 App Bearer 是不同凭证，但解析为同一套内部用户和权限。有效项目成员角色或系统管理员全局权限，由后端事实源判断；Agent 还需满足所请求操作的 scope，确认按钮或 _confirm 不能代替授权。

项目 ACL 是业务访问事实源。图谱、节点、关系、导入导出与查询均须校验项目归属和交叉引用；不能信任前端 user_id、可伪造身份头或客户端声明的资源归属。自由 Cypher、现有静态 Key 和数据库超级用户连接需按正式权限边界收口。
