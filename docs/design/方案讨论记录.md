# Ontology 多用户方案讨论记录

讨论方式：因手机版弹窗交互问题，改为逐项文字提问，确认后再进入下一项。尚未确认的设计建议不作为已决定事项。

## 已确认

1. **按项目协作**：项目默认私有，创建者可以邀请其他人共同查看或编辑。此项由用户选择 B 确认；具体角色、成员管理权限仍待后续讨论。

2. **账号开通方式**：用户选择 A：Workbench 首次登录验证成功后自动创建内部账号；账号密码用户由管理员邀请创建。新用户不自动加入已有项目，不开放账号密码自助注册。

3. **项目创建权限**：用户选择 A：所有已启用用户都可自行创建项目，创建者成为项目所有者；项目默认私有。

4. **项目角色划分**：用户选择 A，采用所有者、管理员、编辑者、查看者四档。所有者可转移所有权及删除项目；管理员协助管理项目和普通成员，不能转移所有权或删除项目；编辑者维护图谱、节点和关系，不能管理成员；查看者只读。

5. **邀请生效方式**：用户选择 A：受邀者接受邀请后才成为项目成员，接受前不具备项目访问权限。

6. **邀请对象范围**：用户选择 A：首版仅向已注册的 Ontology 用户发出站内项目邀请，暂不支持邮件邀请未注册用户；账号开通策略仍沿用第 2 项。

7. **查看者导出权限**：用户选择 B：查看者可以导出其有权访问的图谱数据，但不能修改数据；导出不能扩大项目访问范围。

8. **系统管理员的数据权限**：用户选择 B：系统管理员默认可以查看和管理所有项目。这是独立于项目成员角色的全局权限，相关敏感操作需要审计。

9. **双登录方式的账号绑定**：用户选择 A：支持用户验证两种身份后主动绑定为同一内部账号，账号密码登录与 Workbench 登录共用项目和权限；不根据相同邮箱自动合并。

10. **存量项目归属**：用户选择 A：现有项目及图谱先归指定的初始系统管理员，再由其转交具体负责人；普通用户不自动获得访问权，不能用第一个登录用户代替指定管理员。

11. **Agent 写入权限**：用户选择 A：允许 Agent 在当前用户的项目权限范围内新增、修改和删除数据，写入前需要用户确认；页面与 Agent 共用业务权限，查看者通过 Agent 仍只能读取和导出。

12. **编辑者删除整张图谱的权限**：用户选择 B：编辑者可维护图谱内容，但不能删除整张图谱；整张图谱仅由所有者、项目管理员或系统管理员删除。页面与 Agent 都执行该限制。

13. **成员退出或被移除后的数据归属**：用户确认可以：成员失去项目成员资格后撤销其成员访问权限；其此前创建的图谱、节点和关系继续留在项目中，由其他成员按权限维护，不随成员离开而删除。系统管理员的独立全局权限仍按第 8 项处理。

14. **第一版组织层级范围**：用户选择 A：首版采用用户 → 项目 → 图谱，通过项目邀请实现协作，不增加团队 / 组织层，也不把 Workbench 工作区自动映射为团队或项目。

15. **Workbench 内嵌与登录体验**：用户选择 A：允许新窗口完成登录；浏览器限制内嵌会话时，允许在新窗口使用完整 Ontology 应用，不要求首版全程内嵌。
